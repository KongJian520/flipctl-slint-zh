# The panel's languages

The panel draws words, and the words are not all English any more. This is how a
language gets in, how it gets drawn, and what the base deliberately does not do.

## What is in scope

In: the code-side base — stable ids, one catalogue file per language, a build that
refuses an incomplete catalogue, a runtime switch, and the five places text is drawn.

Out, by decision:

- **Right-to-left and complex scripts.** RTL needs mirrored layout, which Slint does
  not give us today, and neither Arabic nor the Indic scripts have a pixel face to
  draw with. Not a code problem; a materials problem.
- **Per-script font machinery.** A language that needs different glyphs needs a
  different face set, and that is a font swap, not a base concern. See the end.

## Three layers

```
crates/flipper-ui/locales/<locale>.toml     ← 文案的唯一来源
        ↓  build.rs（校验 + 生成）
$OUT_DIR/i18n_generated.rs                  ← LOCALES + TEXTS
        ↓  strings::t()
五个绘制接缝                                 ← 屏幕上出现文字的地方
```

### 1. The catalogue

One file per language, named after the locale id it declares:

```toml
# crates/flipper-ui/locales/zh-Hans.toml
locale = "zh-Hans"
name = "简体中文"

"menu.main.network" = "网络"
"menu.network.airplane" = "飞行模式"
```

`locale` is what `FLIPCTL_LANG` takes; `name` is what the Settings row will show. The
file's name does not have to match `locale`, but matching them is one thing less to
get wrong.

### 2. The build

`build.rs` reads every `*.toml` in `locales/`, in file order, and refuses to build
when the files disagree: a locale missing an id another has, or carrying an id
another does not, fails with the id named. `en` is the source language and must
exist; it is what a half-translated locale falls back to.

The check is a build step rather than a runtime warning because a gap that draws as
a row of English on a panel is a gap nobody notices until a customer does.

### 3. Drawing

`strings::t()` is called where text is drawn, not where it is stored. There are five
such places, and between them they cover ten screens:

| Where | What it covers |
|---|---|
| `demo::apply_menu()` | a menu's rows and its breadcrumb |
| `demo::row()` / `dim()` / `text()` | every detail row's label and value |
| `demo::crumb()` | each segment of a breadcrumb |
| `Live::buttons()` | the soft keys |
| `demo::row_status()` | the status words |

A sixth screen added later reaches the catalogue by going through one of these, which
is the point: an id belongs to a row, and the row is drawn in one of five places.

## Ids

Ids are stable, dotted, lowercase, and describe the thing rather than the text:

```
menu.<screen>.<item>    菜单行与标题
detail.<label>          详情行的标签
action.<verb>           软键
state.<value>           开关、连接状态
led.<item>              LED 子菜单
```

The English text moves when somebody improves the wording; the id must not, because
every translation and every comparison in the code is written against it:

```rust
row.label == "menu.network.modem"    // 而不是 == "5G Modem"
```

A new id needs a line in **every** locale file. The group prefix must be one the
catalogue already has, because a test uses the group list to tell an id from a value
(`tests/keys.rs`).

## The fallback chain

`t()` answers for anything, which is why dynamic values need no special case:

1. the id in the current locale;
2. the id in `en`;
3. the input itself.

So `t("172.17.0.1")` is `172.17.0.1` — it is not an id, and it comes back as it
arrived. And an id nobody translated draws as the id, which is visible in a
screenshot rather than silent.

## The two checks

| Check | Catches |
|---|---|
| `build.rs` | the locale files disagreeing with each other |
| `bin/flipctl/tests/keys.rs` | an id the code uses that the catalogue never heard of |

The second exists because the first cannot see `main.rs`. A missing id draws as
itself — `menu.network.wifi` on a row — which is exactly how it was found.

## Adding a language

1. `cp crates/flipper-ui/locales/en.toml crates/flipper-ui/locales/ja.toml`
2. Change `locale` and `name`, translate the values, keep the ids.
3. `cargo test -p flipctl --test keys` — the catalogue and the code still agree.
4. `FLIPCTL_LANG=ja cargo run -p flipctl --features slint -- --png /tmp/ja.png --screen network`
   and look at it. A language that fits in the tables can still be too wide for the
   panel; `fit()` truncates with `..` and `font::wrap()` breaks long text, but
   somebody has to look.

No code changes, no list to keep in step, nothing to rebuild by hand.

## What the base does not do yet

| 项 | 现状 |
|---|---|
| 持久化 | 无；`FLIPCTL_LANG` 环境变量，默认 `zh-Hans` |
| 设置里的语言行 | 无 |
| `.slint` 里的字面量 | 13 条仍未进目录（`"(no profiles)"`、`"Booting"` 等） |
| 拼接句 | `"{} {} {}"` 拼出的 `IPv4 经 eth0` 只能整段翻译，语序不同的语言要改代码 |
| 复数 | 无；数字后面都是固定单位（`3 sec`、`17 MB`），暂时不需要 |
| 宽字测量 | `BitmapFont.wide` 是每个字体手工声明的常量，不是从字体里读出来的 |

The last one is the coupling to watch: if a face's advance changes, that constant has
to change with it, and nothing currently checks it. `font::fit()` would truncate at
the wrong place rather than fail.

## When to reach for a crate

The base is deliberately small: two hundred lines, no dependency, no build tool
beyond `build.rs`. It stops being the right answer when one of these becomes true:

| 触发 | 换成 |
|---|---|
| 英文开始需要 `1 minute` / `2 minutes` 变格 | Fluent（`.ftl`） |
| 句子里的变量需要改变语序 | Fluent |
| 翻译交给社区或平台（Poedit、Weblate、Crowdin） | gettext（`.po`） |
| 语言超过四、五种，或需要日期与数字格式 | Fluent，或 rust-i18n + ICU |

Swapping one in touches `strings::t` and nothing else: the five seams are the seam.

## Fonts

The three faces carry the scripts the image ships, and the CJK inside them is chosen
when they are built (`tools/font/build-cjk.py`). A language whose script is not in
them draws `?` — the font cannot help it, and the base cannot either. That is a font
set per script, a family per locale, and a decision to make when a language is
actually requested.
